# Project Plan

## 1. Project Methodology

The project team will use the Waterfall Methodology to implement Clinova's SDLC.

### Reasons for Selection

- **Team Size:** Provides clear phases and responsibilities, making teamwork easier to organize.

- **Project Duration:** Helps manage tasks and track progress within the academic timeline.

- **Technology Familiarity:** Provides time to analyze technical requirements and design the system before development.

- **Project Complexity:** Supports detailed analysis and design before implementation.

### SDLC Phases

1. **Planning:** Define project scope, objectives, and feasibility.

2. **Analysis:** Identify and document system requirements.

3. **Design:** Design the system architecture, database, and interfaces.

4. **Implementation:** Develop, test, and deploy the system.

Waterfall is suitable because it offers a structured process in which each phase is completed before moving to the next.

## 4. Coordinating Project Activities

### Project Standards

The Clinova team will follow these standards throughout the Software Development Life Cycle (SDLC):

- **Documentation Standards:** Use consistent formatting, clear titles, dates, and version numbers for all project documents.

- **Coding Standards:** Follow Django and React conventions, use meaningful names, and maintain readable, organized code.

- **Communication Standards:** Hold regular team meetings and record important decisions and progress.

- **Requirements Standards:** Document requirements clearly. Any changes must be reviewed and approved before implementation.

- **Design Standards:** Maintain consistency across interfaces, diagrams, and database designs.

### Project Documentation

All project documents and deliverables must be stored in an organized shared repository.

Key documents include:

- System Request and Feasibility Study.

- Project Plan and Software Requirements Specification (SRS).

- Use Case Diagrams, DFDs, ERDs, and UML Diagrams.

- UI/UX Designs and System Architecture.

- Source Code and API Documentation.

- Test Cases, Test Reports, and Final Documentation.

Documents should be updated when changes occur and maintained with clear version numbers.

### Project Monitoring and Control

The team leader will monitor project progress by:

- Reviewing task completion and team progress.

- Updating the project plan and Jira tasks.

- Comparing actual progress with the planned schedule.

- Identifying delays and addressing problems.

- Controlling changes to prevent scope creep.

### Risk Management

The team should regularly identify and assess project risks based on their likelihood and potential impact.

Important Clinova risks include:

- Unauthorized access to patient medical records.

- Cross-tenant data access.

- Development delays or technical difficulties.

- Changes in project requirements.

- Integration problems with external services.

Each risk should have an appropriate response to reduce its impact.
